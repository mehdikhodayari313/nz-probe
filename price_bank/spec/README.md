# انتقال نتایج قطعی اکسل به برنامه

این پوشه رابط بین فایل‌های اکسل تخمین و کد برنامه است. Claude برای ارتقا **فقط** خلاصه‌های
این پوشه را می‌خواند، نه خود اکسل‌ها را.

```
spec/
  inbox/      اکسل‌ها اینجا آپلود می‌شوند
  pending/    خلاصه‌ی موارد قطعیِ جدید/تغییرکرده — در صف اعمال
  applied/    خلاصه‌هایی که در برنامه اعمال شده‌اند (با شماره‌ی نسخه‌ی برنامه)
  state.json  آخرین وضعیت هر کد (مبنای تشخیص تغییر) — دستی ویرایش نشود
```

## روند کار

1. در اکسل، شیت «خروجی_قطعی» را پر کنید (نمونه و راهنما: `tool/make_export_template.py`).
   فقط ردیف‌های با وضعیت «قطعی» منتقل می‌شوند. اگر عددی عوض شد، «نسخه»ی همان ردیف را بالا ببرید.
2. فایل را در GitHub در پوشه‌ی `price_bank/spec/inbox/` آپلود کنید
   (Add file ← Upload files ← Commit changes).
3. اکشن **spec_extract** خودکار اجرا می‌شود و برای موارد جدید یا تغییرکرده یک فایل
   `.json` (برای Claude) و یک `.md` (برای شما) در `pending/` می‌سازد. هشدارها هم در `.md` هست.
4. در گفتگو بنویسید: «مخزن nz-probe — موارد pending را اعمال کن.»

اگر فایل را مستقیم در گفتگو پیوست کنید هم Claude همین اسکریپت را اجرا می‌کند
(`python3 -I tool/extract_final.py <فایل.xlsx>`) و همین خروجی را می‌سازد.

## انواع ردیف

| نوع | ستون E | توضیح |
|---|---|---|
| ضریب | عدد | ضرایب جنس، فشار، NACE، توان n و … |
| شاخص | عدد | یک مقدار شاخص یا نرخ (سال/ماه در عنوان یا ورودی‌ها) |
| فرمول | فرمول اکسل | فرمول و مقدار همه‌ی سلول‌های ارجاعی خودکار خوانده می‌شود |
| جدول | آدرس محدوده (متن) | مثل `'ضرایب'!A1:D12`؛ سطر اول عنوان ستون‌ها |
| آزمون | عدد مورد انتظار | ورودی‌ها در ستون J؛ برنامه باید دقیقاً همین عدد را بدهد |
| قاعده | متن | قاعده‌ی منطقی که با عدد بیان نمی‌شود |

ردیف‌های «آزمون» مهم‌ترین بخش‌اند: هر فرمولی که منتقل شود، با آزمون‌های همان رده در برنامه
بررسی می‌شود و نسخه‌ای که با اکسل نخواند ساخته نمی‌شود.
