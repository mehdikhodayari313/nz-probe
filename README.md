# برنامه‌ی آزمایشی سنجش سازگاری — بانک قیمت نمک‌زدایی

این برنامه پیش از ساخت نرم‌افزار اصلی بررسی می‌کند که روی **سیستم‌های شرکت** (و گوشی اندروید) مانعی برای اجرا وجود ندارد.
همه‌ی فناوری‌هایی که برنامه‌ی اصلی لازم دارد اینجا واقعاً اجرا می‌شوند:

| آزمون | چه چیزی را ثابت می‌کند |
|---|---|
| سیستم‌عامل | نسخه‌ی ویندوز مناسب است (۱۰ یا ۱۱، ۶۴ بیتی) |
| دسترسی نوشتن | برنامه بدون دسترسی Administrator می‌تواند داده ذخیره کند؛ حالت قابل‌حمل (کنار exe) هم سنجیده می‌شود |
| SQLite | دیتابیس محلی ساخته می‌شود، ۲۰٬۰۰۰ رکورد ثبت و دوباره خوانده می‌شود، متن فارسی سالم می‌ماند، آنتی‌ویروس مانع یا کندکننده نیست |
| تاریخ شمسی | تبدیل تاریخ درست است (نوروز ۱۴۰۳ و ۱۴۰۴ به‌عنوان مرجع) |
| موتور شاخص‌ها | ضریب تورم تجمعی ۱۳۹۲→۱۴۰۵ **دقیقاً** برابر عدد فایل مارون ۳ (۴۹٫۷۸۹…) است؛ جستجوی ماه ← فصل ← سال کار می‌کند |
| خواننده‌ی اکسل | فایل نمونه با سه ایراد عمدی درست خوانده و ایرادها پیدا می‌شوند |
| نمایش فارسی | (تأیید چشمی شما) حروف و ترتیب کلمات فارسی/انگلیسی/عدد درست است |
| فایل‌های واقعی | فایل‌های MTO و برآورد شما خوانده، قالبشان تشخیص داده و اقلام و ایرادها شمرده می‌شوند |

برنامه **به هیچ شبکه‌ای وصل نمی‌شود**، فایل‌های اکسل را فقط می‌خواند و فایل آزمایشی دیتابیس را پس از آزمون پاک می‌کند.

---

## مرحله‌ی ۱ — آماده کردن سیستم خودتان (فقط یک بار)

این کار روی **رایانه‌ی شخصی شما** انجام می‌شود، نه سیستم شرکت.

1. **Flutter SDK** (نسخه‌ی ۳٫۲۷ یا جدیدتر) را از سایت رسمی Flutter دریافت و در مسیری مثل `C:\flutter` باز کنید.
   مسیر `C:\flutter\bin` را به PATH ویندوز اضافه کنید.
   > دریافت Flutter و بسته‌ها ممکن است از داخل ایران به اینترنت بین‌الملل نیاز داشته باشد. فقط همین مرحله اینترنت لازم دارد؛ خود برنامه هرگز.
2. **Visual Studio 2022 Community** را با بخش **Desktop development with C++** نصب کنید (برای ساخت برنامه‌ی ویندوز لازم است).
3. (اختیاری، فقط برای نسخه‌ی اندروید) **Android Studio** را نصب کنید.
4. در یک پنجره‌ی cmd دستور زیر را بزنید و مطمئن شوید بخش‌های Windows (و در صورت نیاز Android) تیک سبز دارند:
   ```
   flutter doctor
   ```

## مرحله‌ی ۲ — ساخت برنامه

روی فایل `build_windows.bat` دوبار کلیک کنید. این اسکریپت به ترتیب:

1. پوشه‌های ویندوز و اندروید را می‌سازد،
2. بسته‌ها را دریافت می‌کند،
3. کد را تحلیل می‌کند (`flutter analyze`)،
4. **همه‌ی آزمون‌های خودکار** را اجرا می‌کند (`flutter test`)،
5. نسخه‌ی نهایی را می‌سازد،
6. فایل‌های Visual C++ را کنار برنامه می‌گذارد تا روی سیستم شرکت نصب چیزی لازم نباشد،
   و همه را در `dist\nz_probe_windows.zip` بسته‌بندی می‌کند. شناسه‌ی SHA-256 فایل هم برای واحد IT ساخته می‌شود.

اگر در هر مرحله خطایی دیدید، متن خطا را کامل کپی کنید و برای Claude بفرستید.

برای اندروید: `build_android.bat` ← فایل `dist\nz_probe_android.apk`.

## مرحله‌ی ۳ — اجرا روی سیستم شرکت

1. فایل `nz_probe_windows.zip` را با فلش به سیستم شرکت ببرید و **از حالت فشرده خارج کنید** (اجرای مستقیم از داخل zip کار نمی‌کند).
2. `nz_probe.exe` را اجرا کنید. نیازی به نصب یا دسترسی Administrator نیست.
3. صبر کنید آزمون‌های خودکار تمام شوند (چند ثانیه).
4. در کادر «نمایش متن فارسی» یکی از دو دکمه را بزنید.
5. «انتخاب فایل» را بزنید و فایل‌های پازنان ۲، KPL، گچساران ۴ و مارون ۳ را با هم انتخاب کنید.
6. «ذخیره‌ی گزارش» را بزنید و فایل گزارش را برای Claude بفرستید.

اگر سیستم‌های مختلفی در شرکت دارید (ویندوز ۱۰ و ۱۱، واحدهای مختلف)، آزمون را روی دو سه سیستم تکرار کنید.

## دریافت نسخه‌ی آماده از GitHub (بدون نصب Flutter)

با هر تغییر در شاخه‌ی `main`، GitHub به‌طور خودکار روی یک ویندوز ابری این کارها را انجام می‌دهد:
تحلیل کد، اجرای همه‌ی تست‌ها، ساخت نسخه‌ی ویندوز و اندروید، و **اجرای خود برنامه‌ی ساخته‌شده در حالت خودآزمایی**.

برای دریافت:
1. در صفحه‌ی مخزن، زبانه‌ی **Actions** را باز کنید.
2. آخرین اجرای **build** که تیک سبز دارد را باز کنید.
3. پایین صفحه در بخش **Artifacts**:
   - `nz_probe_windows` ← نسخه‌ی ویندوز
   - `nz_probe_android` ← فایل APK اندروید
4. فایل دانلودشده یک zip است که مستقیم `nz_probe.exe` و فایل‌های کنارش داخل آن است. آن را با «Extract to nz_probe_windows\» در یک پوشه‌ی جدید باز کنید (نه Extract Here روی دسکتاپ) و `nz_probe.exe` را اجرا کنید.

## حالت خودآزمایی بدون رابط کاربری

برای واحد IT یا اجرای خودکار:
```
nz_probe.exe --selftest C:\temp\report.txt
```
همه‌ی آزمون‌های خودکار اجرا می‌شوند، گزارش ذخیره می‌شود و برنامه با کد ۰ (موفق) یا ۱ (ناموفق) بسته می‌شود.

## اگر برنامه اجرا نشد

| نشانه | علت محتمل | راه‌حل |
|---|---|---|
| خطای «Cannot create … being used by another process» هنگام باز کردن zip | استخراج روی همان پوشه‌ای که فایل zip در آن باز است | «Extract to پوشه‌ی جدید» را بزنید |
| پیام «Windows protected your PC» | SmartScreen؛ فایل از اینترنت یا پیام‌رسان آمده | More info ← Run anyway؛ یا انتقال با فلش |
| پیام «This app has been blocked by your system administrator» | AppLocker یا سیاست لیست سفید | واحد IT باید برنامه را مجاز کند (شناسه‌ی SHA-256 در فایل `.sha256` هست) |
| برنامه باز نمی‌شود و آنتی‌ویروس هشدار می‌دهد | برنامه‌ی ناشناس بدون امضای دیجیتال | استثنا در آنتی‌ویروس توسط IT |
| خطای `VCRUNTIME140.dll was not found` | فایل‌های Visual C++ کنار exe نیستند | از zip ساخته‌شده با `build_windows.bat` استفاده کنید |
| آزمون SQLite «کند» گزارش شد | اسکن هم‌زمان آنتی‌ویروس | استثنا برای پوشه‌ی داده‌ی برنامه |
| هشدار «پوشه‌ی داده روی شبکه است» | Folder Redirection پروفایل کاربر | در برنامه‌ی اصلی مسیر دیتابیس قابل تنظیم خواهد بود |

## آزمون با فایل‌های واقعی در محیط توسعه (اختیاری)

فایل‌های اکسل را در پوشه‌ی `test\fixtures` کپی کنید و `flutter test` را اجرا کنید.
برای پازنان ۲ و KPL تعداد اقلام و قیمت‌ها با نتیجه‌ی خواندن مستقل با پایتون مقایسه می‌شود
(پازنان ۲: ۵۶ قلم و ۱۰۳ قیمت؛ KPL: ۱۲۰ قلم و ۱۲۰ قیمت).
این فایل‌ها در `.gitignore` هستند و وارد مخزن کد نمی‌شوند.

## ساختار کد

```
lib/
  core/                 ← هسته‌ی مستقل از رابط کاربری؛ مستقیم به برنامه‌ی اصلی منتقل می‌شود
    xlsx/xlsx_reader.dart     خواننده‌ی سبک xlsx (zip + XML)، بدون نیاز به اکسل
    xlsx/sample_xlsx.dart     فایل نمونه برای خودآزمایی
    mto/mto_scan.dart         تشخیص قالب MTO و شمارش اقلام و ایرادها
    indices/index_engine.dart شاخص‌ها و نرخ ارز با دقت سال/فصل/ماه
  probe/                ← آزمون‌های سازگاری و مدیریت اجرای آن‌ها
  ui/                   ← رابط کاربری فارسی راست‌به‌چپ
test/                   ← آزمون‌های خودکار
```

فونت: وزیرمتن (مجوز آزاد OFL، داخل `assets/fonts`).
